# Windows redistribution audit — NOT RELEASE-CLEARED

**Historical initial-bundle audit.** The final Preview 2 media/shader runtime differs from the bundle examined here. See [current release provenance](../RELEASE-PROVENANCE.md), the MSYS2 source records and final package verification. Findings below are preserved as investigation history, not silently converted into clearance claims.

This is an evidence collection and repaired staging tree, not a declaration that all redistribution obligations have been met. Do not label the entire package simply GPL: proprietary Microsoft components, LGPL Qt, zlib SDL, MIT/BSD/Apache libraries, MPL Rhino and GPL components coexist.

## Runtime and verification

Original: `/data/VMs/cloudstream-windows10/CloudStream-Windows-x64.zip`.
Staging: `/data/CloudStream-releases/0.1.0-preview.2/windows-runtime`.
`original-runtime-inventory.json` records SHA-256 for the original ZIP and all 585 retained files. Backslashes were normalized, traversal/absolute/drive/symlink/duplicate entries rejected, and ZIP CRC checked while extracting. Eight verification logs/screenshots were omitted; no user data fixtures were present outside that directory. No executable or DLL was replaced. Existing `runtime/legal`, NOTICE, release metadata and Java `lib/src.zip` remain intact.

This preserves the previously Windows-tested payload, not a fresh target execution. No VM was modified or launched. `pe-imports.json` is static PE dependency evidence, not a clean Windows smoke test. IMPORTANT: the original ZIP requires installation of its `vc_redist.x64.exe`; MSVCP140.dll, MSVCP140_1.dll, MSVCP140_2.dll, VCRUNTIME140.dll and VCRUNTIME140_1.dll are not app-local beside cloudstream.exe. The Java copies alone do not satisfy Qt's loader search/dependency closure. NSIS must install/check the redistributable, and the portable ZIP is NOT zero-prerequisite.

## Native components and sources

* **Qt 6.8.3, MSVC2022 x64**: qtbase and qtsvg exact version source archives are in `third-party-sources`. Their actual LICENSES, third-party license texts and Qt attribution JSON files are copied under `licenses/source-licenses`. Deployed modules are Core, Gui, Network, Widgets, OpenGL, OpenGLWidgets, Svg and associated plugins. Qt is available under LGPL-3.0/GPL alternatives (individual source file terms govern); the commercial license is not assumed. The shared DLLs remain replaceable. Users may modify/replace LGPL components and reverse-engineer the application for debugging such modifications; no installer terms should contradict those rights. Exact Qt installer-component archive hashes/configuration and build flags were not recovered, so the unmodified-release correspondence is a build-history assertion rather than a binary hash comparison. Resolve that gap and fulfill chosen Qt LGPL/GPL source/relinking obligations before release.
* **mpv shinchiro 20260903, 69e63f425a**: libmpv-2.dll is byte-identical to the release's mpv-dev-x86_64 archive. Source snapshot at 69e63f425a, actual COPYING/LICENSE texts, the build scripts at workflow head cd1edc11dc6887a50f705717619d879f5a93a488, release metadata and workflow-run metadata were collected. Associated FFmpeg revision 9fc8c785e source is also supplied. mpv's GPL/LGPL configuration must be treated with its enabled dependencies, not inferred from dynamic linkage. **BLOCKER:** these archives do not contain the complete exact source revisions, patches, license notices and build inputs of all statically linked dependencies. * **Mesa 26.2.0 pal1000 MSVC**: libgallium_wgl.dll and opengl32sw.dll match the release x64 DLLs (opengl32sw.dll is upstream opengl32.dll renamed, bytes unchanged). Exact Mesa source and pal1000 26.2.0 build scripts supplied, with actual Mesa license documentation. ## Additional findings and source-support packaging

The source collection has been moved out of the binary runtime into sibling `windows-source-support/`, and packaged separately as `CloudStream-0.1.0-preview.2-Windows-source-support.tar`. References above to `third-party-sources` identify the `sources/` directory inside that support archive. The archive is intentionally uncompressed tar because its source tarballs/JARs are already compressed. It contains source SHA-256 inventory, licenses and provenance evidence; it is still partial corresponding source, not a clearance certificate. Serve it alongside any eventual binary release only after the unresolved closure obligations are handled.

It was therefore NOT removed in this audit. The parent may remove it only after narrowing supported rendering backends and validating the changed final runtime; current static imports alone cannot prove optional DLLs unused.

Mesa's archived MSVC buildinfo identifies LLVM 22.1.8, zlib 1.3.2, zstd 1.5.7, SPIRV Tools 2026.3.1, Vulkan SDK 1.4.357.0 and DirectX headers 1.619.5. Exact-version LLVM, zlib and zstd license texts were added. The attempted SPIRV Tools v2026.3.1 license URL returned 404, retained in download receipts. This improves attribution but does not erase the remaining whole-static-build attribution review.

## How to distribute once cleared

Keep `licenses/`, `THIRD-PARTY-NOTICES.txt`, Java legal files and `third-party-sources/` with the release or provide the legally appropriate corresponding-source delivery mechanism alongside binaries. The source archives here are a partial collection, not a complete source offer. Do not silently drop them to reduce installer size and claim compliance. Apply the application's own GPL terms separately; preserve third-party copyright and exception text. No restriction on replacement of LGPL DLLs or MPL source access may be introduced.

`downloads*.json` are URL/hash receipts. Binary ZIP/7z comparison inputs were downloaded, compared, then deleted to avoid shipping duplicate executables; their paths in receipts are historical scratch paths. Source archives remain in staging and license evidence remains in this directory. False comparisons deliberately remain recorded; they are unresolved findings, not omitted failures.
